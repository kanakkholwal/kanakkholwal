## Overview

Orbit Files started as a PDF toolkit and is now a full set of file tools for PDFs, photos, video, audio and documents. It does everything on your own device and never uploads a thing. It works in the browser, installs as a PWA on mobile with offline caching, and ships as a Tauri desktop app for anyone who would rather have it as a real app.

## The problem

I built Orbit because I did not trust the web for something as simple as merging a PDF. Most online PDF tools upload your file to their server first, and when a document is sensitive that is a real problem: you have no idea whether it is stored, trained on, or leaked.

## Wins

- **Private by default.** Everything runs locally in your browser's sandbox. No uploads, no server, no telemetry on your documents.
- **Fast.** The heavy lifting runs on a WebAssembly engine, so processing feels desktop-class.
- **Works offline.** Fully functional with no connection. Install it as a PWA on mobile, or grab the Tauri desktop build.
- **No limits.** No daily quotas, no file size caps, and no subscriptions. Batch as much as your machine can handle.

It began with the everyday PDF jobs (merge, split, compress, image to PDF) and has grown well past them:

- **PDF:** edit, sign (eSign and real PAdES digital signatures), OCR, encrypt, redact metadata, fill forms, compare, and convert to and from Word, Excel, PowerPoint and Markdown.
- **Beyond PDF:** background remover, photo resize and convert, video and audio editors, QR code generator, file hash, favicon and colour palette tools.
- **Everywhere:** website, installable PWA, and a desktop app for Windows, macOS and Linux.

Nothing here is groundbreaking. It is convenience done properly: a clean UI, sane defaults, and your files staying yours.

## How it's built

The constraints were simple from day one: lightweight, private, and offline. Each tool is a route in one SvelteKit app, and everything runs client side. PDF page work runs on [`pdf-lib`](https://pdf-lib.js.org/) and [`pdfjs-dist`](https://mozilla.github.io/pdf.js/), and heavy operations like compression run on [`qpdf-wasm`](https://github.com/neslinesli93/qpdf-wasm), so they are fast without a server.
